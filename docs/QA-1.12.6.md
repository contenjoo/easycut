# 1.12.6 / Windows 0.6.3: 부분 배속과 파형

## 변경

- 배속 변경 전 시간축으로 자막 시작과 끝을 구간별 선형 변환한다. 앞쪽은 유지하고, 배속 구간 안은 비율에 맞추며, 뒤쪽은 길이 변화만큼 이동한다.
- 복수 클립은 한 번에 처리해 순서 의존성과 겹친 트랙의 중복 자막 변환을 방지한다.
- 여러 트랙에서 자막 기준은 겹친 구간의 대본·소리·영상 순으로 선택한다. 자막에 명시적인 원본 클립 연결이 없는 기존 프로젝트 형식을 유지한다.
- 영상 파형은 기존 고정 16포인트 대신 제목 아래 공간을 사용한다. 기본 트랙에서는 28포인트 이상, 트랙이 커지면 함께 확대된다. 실제 음량은 바꾸지 않는다.

## macOS 실제 확인

- 12초 영상의 4~8초 구간만 실제 클립 인스펙터의 `2x` 버튼으로 변경했다.
- 클립 길이 4초 → 2초, 전체 길이 12초 → 10초를 확인했다.
- 자막 목록: 앞 1.00초 유지, 구간 안 4.50초 → 4.25초, 뒤 8.50초 → 6.50초.
- 4.25초로 이동했을 때 영상의 원본 시간 4.50초와 `두 번째 소리` 자막이 함께 표시됐다.
- UI에서 실행 취소하면 4.50/8.50초로 복원되고, 다시 실행하면 4.25/6.50초로 돌아오는 것을 확인했다.
- UI로 저장한 `/tmp/easycut-speed-qa/ui-applied.easycut`의 실제 JSON에서 클립 속도 `[1,2,1]`과 자막 시작 `[1,4.25,6.5]`를 확인했다.
- 같은 검증 영상에서 기존 앱과 새 앱의 파형 높이를 실제 화면으로 비교했다.

## 자동 검사와 실제 출력

`EASYCUT_SELFTEST_ONLY=speed-caption EasyCut --selftest /tmp/easycut-speed-qa`

부분 배속, 경계 자막, 0.5배속, 복수 선택·트랙, 실행 취소·다시 실행, 파형 크기와 실제 내보내기 등 21개 통과.
일정한 원본 시점에 소리가 나는 영상을 실제 앱 내보내기 엔진으로 출력하고 오디오를 다시 분석했다.
3개 자막 모두 시작과 출력 소리의 시작 차이가 50ms 이내이며 출력 길이는 10초였다.
기존 자막 입력 회귀 검사도 23개 통과했다.

Windows Rust 코어 검사 31개(새 배속 검사 5개 포함) 통과.
실제 Windows WebView2 검사에 부분 배속·자막 시각·실행 취소·다시 실행과 실제 파형 렌더러 높이 검사를 추가했다.
그 실행 결과와 설치파일은 GitHub Actions의 해당 릴리스 태그 실행에서 별도로 확인한다.
